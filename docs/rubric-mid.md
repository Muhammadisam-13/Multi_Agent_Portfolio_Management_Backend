# FYP-1 Mid evaluation — what is graded (supervisor-only, formative, 20% of FYP-1)

Source: FYP-1 Mid Evaluation Guidelines & Rubrics (PDF given by the university).

## Form 2: presentation and demo (100 marks)
| # | Criterion | Marks | Notes / caps |
|---|---|---|---|
| 1 | Previous proposal actions addressed (Panel Action Register, Form 10) | 10 | Ignored actions cap progress marks |
| 2 | Iteration plan and work breakdown progress | 10 | Honest delay + recovery plan with owners is acceptable |
| 3 | **Live prototype, core module demo** | 25 | Must be live (no screenshots/video). Happy path only: 16-20. Edge/failure cases shown: 21-25. Hardcoded scaffolding: 11-15 |
| 4 | Requirements and acceptance criteria quality | 10 | Numbered, testable FRs/NFRs tied to implementation |
| 5 | Design artefacts and design evolution | 15 | Diagrams must match code; diagrams-only caps at 50% |
| 6 | Repository, milestone, member evidence | 10 | Commits from all members; no real VCS caps at 40% |
| 7 | Testing and early validation | 10 | Executed tests with logs, failure case discussed |
| 8 | Presentation, Q&A, team and tool ownership | 10 | Every member must explain their own module; weak member triggers Form 11 |

## Form 3: report (8 criteria)
Format/template (5), problem + R&D + gap (15), vision/scope/success criteria (10), requirements + acceptance (15),
architecture + interfaces (15), data/process/behavior design (10), implementation documentation with reproducible setup (15),
testing plan + tool/risk disclosure (15). Tool-use disclosure item is 0 until full GenAI/tool disclosure is submitted.

## Red flags supervisors probe
Sudden large code the student cannot explain line by line; prototype barely beyond proposal POC-lite;
generic AI-written R&D text; one member carrying everything; milestone log claiming done what the demo does not show;
ignored proposal panel actions.

## Priority order for effort
Working live demo with a failure case > Panel Action Register > commits from all members > tests with logs >
report sections (SRS, architecture matching code, setup steps, tool disclosure) > polish.
